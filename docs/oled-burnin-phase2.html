Current state: Both PRs are built, host-tested, and hardware-verified on AMOLED-1.43 (2026-05-26). PR-1 (adapter scaffold + push/button/touch wakes) is PR #48; PR-2 (QMI8658 motion wake on a stacked branch) is PR #49. All five FSD § 8.2 acceptance tests for Phase 2 (DIM-001, DIM-002, WAKE-001..005) have passed; only the 24 h soak (AT-1) is still outstanding.

2. PR-1 — adapter scaffold + push / button / touch wakes

Status

✅ Verified on hardware PR #48 · branch feat/oled-burnin-phase2 · head 986c0ed (3 Copilot review passes + hardware verification 2026-05-26)

Wires the SM into the AMOLED display profile end-to-end with three of the four planned wake sources (push, button, touch). Motion wake ships in PR-2 alongside the QMI8658 driver port. Touch wake is included via polling — the FT3168 INT line is not routed on the Waveshare 1.43″ board, and the vendor LVGL demo (08_LVGL_SDIMG) confirms the working pattern is to read the controller from an LVGL input-device callback at ~30 Hz, which keeps ticking when the panel is asleep.

firmware/main/displays/amoled_sh8601/qmi8658.{c,h} New. Minimal port of docs/ESP32-S3-AMOLED-1.43-Demo/03_I2C_QMI8658/components/qmi8658c/. Attaches to the I²C0 bus already installed by touch.c in PR-1. Probes both 0x6A and 0x6B (this board responds at 0x6B — SA0 wiring differs between revs). Exposes qmi8658_init() and qmi8658_read_accel_mg(int16_t out[3]). Accelerometer only — gyro paths in the vendor demo are dropped (FR-1.5). ODR Qmi8658AccOdr_LowPower_21Hz, ±2 g range, LPF disabled. firmware/main/displays/amoled_sh8601/burn_idle_adapter.c IMU sampler task at ~21 Hz using xTaskDelayUntil (steady cadence anchored to an absolute tick reference). Computes per-axis |new − last_posted| in mg; on cross of MOTION_THRESHOLD_MG, posts EV_MOTION with a 200 ms per-event debounce. Compares against the last-posted sample (not the previous raw) so a slow drag doesn't fire continuously. Baseline is set from the first successful read so the ~1 g gravity vector doesn't trigger a spurious EV_MOTION at startup. Failure of qmi8658_init or the sampler task spawn is non-fatal — the adapter falls back to three wake sources. ✅ Done
firmware/main/displays/amoled_sh8601/sources.cmake Added qmi8658.c to the AMOLED profile build. ✅ Done

4. Out of scope for Phase 2

Cleanly deferred to future phases — not blocked by anything here:

  • Orientation rotation (FSD Phase 3, FR-1.x). Reads the accelerometer gravity vector and rotates the LVGL display in 90° steps. The QMI8658 port shipped in PR-2 is reusable.
  • Palette / soft-edge constraints (FSD Phase 4, FR-5 / FR-6). Build-time validator for no-pure-white / no-saturated-blue; LVGL anti-aliasing enabled.
  • Telemetry on idle SM transitions exposed via GET /health (FSD Known Gap G-3).
  • Pixel-shift / orbit (catalog § 1.1). Coarse spatial diversity comes from orientation rotation; full pixel-shift would be a separate FSD.
